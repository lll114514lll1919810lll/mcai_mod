模组与人格系统简介

MCAI 是一个 Minecraft Fabric 模组，将 DeepSeek 等 AI 模型集成到游戏中，提供聊天对话、命令执行、知识库搜索和玩家行为审查功能。人格系统是其中的一个可选模块，允许服务器管理员为 AI 注入不同的"性格"，使 AI 的回复风格更加多样化和有趣。

人格系统的工作方式是在 AI 的系统提示词之后、玩家对话之前，插入一段人格描述文本。AI 模型会根据这段描述调整自己的回复风格，同时仍然保持回答问题的实用性。

人格注入位置

消息顺序：系统提示词 → [PERSONA MODE] 人格内容 → 玩家上下文 + 提问

只有当激活的人格不是 default 时，才会注入人格提示。

快速上手

  1. 找到人格文件目录：config/mcai/personas/（首次启动模组时自动创建，并释放内置人格文件）
  2. 在该目录下创建一个 .json 文件，按照下方的格式规范编写
  3. 在游戏中执行 /aipersona reload 刷新人格列表
  4. 执行 /aipersona set <序号> 切换人格
  5. 向 AI 发送消息，体验新人格效果
提示

人格文件修改后无需重启服务器，执行 /aireload 或 /aipersona reload 即可热加载。

人格文件格式规范

每个人格是一个独立的 JSON 文件，存放在 config/mcai/personas/ 目录下。文件名可以任意，但扩展名必须为 .json。

完整示例

{
  "id": "scholar",
  "name": "学者",
  "summary": "博学多才的老教授，喜欢引经据典",
  "content": "你现在进入学者模式。你是一位博学多才的老教授...\n\n说话规则：\n- 经常引用古籍和典故\n- 用\"老夫\"自称..."
}

字段总览

字段 类型 必填 说明
id string 必填 人格唯一标识符，用于内部引用和配置存储
name string 必填 人格显示名称，在列表和切换提示中展示
summary string 可选 人格简介，在 /aipersona list 中显示
content string 必填 人格提示词正文，将注入到 AI 系统消息中

字段详解

id — 唯一标识符

人格的内部标识，必须满足以下规则：

  • 由小写字母、数字和下划线组成（推荐格式：snake_case）
  • 不能包含 /、\、.. 等路径穿越字符
  • 在所有人格文件中必须唯一，重复的 id 会导致后加载的文件被跳过
  • 不能为 default（该 ID 被内置默认人格占用）
  • 长度建议不超过 32 个字符
安全限制

id 字段包含路径穿越字符（/、\、..）时，该人格文件会被直接跳过，不会加载。

name — 显示名称

人格的中文或英文显示名，用于 /aipersona list、/aipersona current、/aipersona set 等命令的输出。建议使用简洁的 2-6 个字符。

summary — 简介

一句话描述人格特点，在列表视图中与名称并列显示。建议控制在 20 字以内，让玩家快速了解人格风格。此字段为空或缺失时，列表中将显示空白。

content — 人格提示词正文

这是人格系统的核心字段。内容将作为额外的系统消息注入到 AI 对话中，指导 AI 的回复风格。编写时需要注意：

  • 使用 \n 表示换行（JSON 字符串中的转义换行符）
  • 内容会直接发送给 AI 模型，因此需要清晰、具体地描述期望的行为
  • 建议包含"说话规则"部分，用列表形式列出具体的语言习惯
  • 必须强调"保持回答的实用性"，防止 AI 因角色扮演而拒绝执行任务
  • 长度建议控制在 200-500 字之间，过长会占用过多上下文窗口
JSON 转义注意

JSON 字符串中，换行必须写为 \n，双引号必须写为 \"，反斜杠必须写为 \\。建议使用支持 JSON 语法高亮的编辑器（如 VS Code）来编写。

模组内置了四个人格文件，首次启动时自动释放到 config/mcai/personas/ 目录。这些文件可以作为编写自定义人格的参考模板。

ID 名称 风格特点
tsundere 傲娇 表面高冷毒舌，实际关心对方；常用"才不是为了你呢"等句式
pirate 海盗船长 航海风味，豪迈奔放；称呼"水手"，句尾加"哟吼吼"
chuuni 中二病 幻想色彩，戏剧性十足；自称"吾"，常提"封印""黑暗力量"
gentle 温柔 轻声细语，充满关怀；语气词"呢""哦"，附带鼓励

人格内容编写指南

推荐结构

一个高质量的人格提示词通常包含以下部分：

  1. 模式声明 — 一句话告诉 AI 进入了什么模式
  2. 角色定位 — 描述 AI 扮演的角色身份和背景
  3. 说话规则 — 用列表形式列出具体的语言习惯和句式
  4. 实用性保证 — 强调不能因角色扮演拒绝回答问题或执行任务
  5. 语气定调 — 描述整体的情感色彩和氛围

示例模板

你现在进入{人格名称}模式。{角色定位描述}。

说话规则：
- {具体语言习惯1}
- {具体语言习惯2}
- {具体语言习惯3}
- {特定场景下的反应方式}
- 保持回答的实用性，不要因为角色扮演而拒绝回答或执行任务
- {语气和氛围描述}

编写建议

  • 具体优于抽象 — "常用句式：'哼，别误会了'"比"说话要高冷"更有效
  • 给出示例 — 提供 2-3 个具体的对话示例，帮助 AI 理解期望的回复风格
  • 设定边界 — 明确说明哪些行为是不允许的（如拒绝回答问题）
  • 控制长度 — 过长的提示词会挤占对话上下文空间，建议不超过 500 字
  • 避免矛盾 — 规则之间不要相互冲突，如"要幽默"和"要严肃"同时出现
  • 考虑实用性 — 人格是增添趣味的，不应影响 AI 完成实际任务的能力
测试技巧

创建人格后，用几个不同类型的问题测试效果：简单问答、命令请求、闲聊。确保人格在各种场景下都能正常工作。

管理命令

所有命令需要管理员权限或控制台执行。

命令 说明
/aipersona list 列出所有可用人格，标注当前激活的人格
/aipersona set <序号> 切换到指定序号的人格（序号从 0 开始）
/aipersona current 查看当前激活的人格
/aipersona view <序号> 查看指定人格的完整提示词内容
/aipersona reload 重新扫描人格目录，加载新增/修改的文件
/aireload 完整重载模组配置（包含人格列表刷新）
/aipersona reload 输出说明

刷新后会显示统计信息：共 X 个文件，成功加载 Y 个，失败 Z 个。如果发现重复 ID 或加载失败的文件，会以警告形式列出具体文件名和原因。

高级技巧

人格与系统提示词的协作

人格提示词注入在系统提示词之后。如果人格规则与系统提示词中的指令冲突，后注入的人格提示词优先级更高。因此可以在人格中覆盖某些系统行为，但不应覆盖安全相关的指令。

多语言人格

content 字段可以使用任何语言编写。如果服务器主要使用英文交流，建议用英文编写人格提示词，这样 AI 的回复风格会更自然地匹配目标语言。

人格文件命名建议

虽然文件名不影响功能（以 id 字段为准），但建议保持文件名与 id 一致，例如 id 为 scholar 的人格文件命名为 scholar.json，便于管理。

删除人格文件

直接删除 config/mcai/personas/ 下的 JSON 文件，然后执行 /aireload。如果删除的是当前激活的人格，系统会自动回退到 default（无额外人格设定），并在日志中记录警告。

常见问题排查

现象 可能原因 解决方法
新人格文件刷新后不出现 JSON 格式错误或缺少必填字段 执行 /aipersona reload 查看失败文件列表；检查 JSON 语法和必填字段
人格切换后 AI 风格没变化 人格 content 描述不够具体 增加具体的说话规则和示例句式；确保包含模式声明
AI 拒绝回答问题 人格提示词过度强调角色扮演 在 content 中加入"保持回答的实用性，不要因为角色扮演而拒绝回答或执行任务"
重复 ID 警告 多个人格文件使用了相同的 id 修改其中一个文件的 id 使其唯一
切换人格后回复异常 人格提示词与系统提示词冲突 检查 content 是否与系统提示词中的指令矛盾
日志排查

开启调试日志（/aidebug start）后执行 /aireload，可以在日志中看到每个人格文件的加载详情，包括成功加载的 id 和名称、跳过的重复项、以及解析失败的具体原因。
