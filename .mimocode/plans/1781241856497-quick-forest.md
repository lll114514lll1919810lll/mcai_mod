# 拆分 ChatHandler 计划

## 目标

将 `ChatHandler.java`（751 行，6 个混合职责）拆分为 1 个精简编排器 + 6 个专职类。

---

## 拆分方案

### ChatHandler 现存职责

| # | 职责 | 提取目标 | 说明 |
|---|------|---------|------|
| 1 | 聊天日志（chatLog 读写/清除） | `ChatLog` | 线程安全有界缓冲区 |
| 2 | 思考动画（经验栏闪烁） | `ThinkingAnimation` | ScheduledExecutorService |
| 3 | 玩家上下文构建 | `PlayerContextBuilder` | 位置/状态/进度 → 字符串 |
| 4 | 命令执行 + 审批系统 | `CommandExecutionService` | 合并 approve 和执行逻辑 |
| 5 | 工具调用分发（if-else 链） | `ToolDispatcher` | 消除 handleAIQuery 和控制台的重复 |
| 6 | Brigadier 命令注册 | `CommandRegistry` | 7 个命令，纯委派层 |

### 1. `ChatLog` — 聊天日志
```java
public class ChatLog {
    private final LinkedList<String> log = new LinkedList<>();
    public void add(String name, String message)
    public void add(String name, String message, boolean isAdmin)  // 管理员标记
    public String peek()
    public void clear()
}
```

### 2. `ThinkingAnimation` — 思考动画
```java
public class ThinkingAnimation {
    public void start(ServerPlayerEntity player)
    public void stop(UUID playerId)
    public void done(ServerPlayerEntity player)
}
```

### 3. `PlayerContextBuilder` — 玩家上下文
```java
public class PlayerContextBuilder {
    public String build(ServerPlayerEntity player)
}
```
提取 `buildPlayerContext` + `formatGameTime`。纯函数，无状态。

### 4. `CommandExecutionService` — 命令执行 + 审批
```java
public class CommandExecutionService {
    // 从 ChatHandler 移入
    private final ConcurrentMap<UUID, List<String>> pendingCommands;
    private final ConcurrentMap<String, CompletableFuture<String>> pendingFutures;

    public String executeCommand(String command, ServerPlayerEntity player)
    // 检查 needsApproval → 需要则阻塞等审批，否则立即执行

    public String executeAsOp(String command, MinecraftServer server)
    // 以 OP 权限直接执行命令，捕获输出（消除 approveCommand 和 executeCommand 中的重复构造）

    public int approveCommand(ServerPlayerEntity admin, int num)
    public int rejectCommand(ServerPlayerEntity admin, int num)
    public boolean needsApproval(String command)
    public void cleanupPlayer(UUID playerId)
    public List<String> getPendingCommands(UUID playerId)
}
```

**关键设计决策**：将 `approveCommand` 中的命令执行逻辑和 `executeCommand` 中的「直接执行」分支合并为统一的 `executeAsOp` 方法，消除重复的 `ServerCommandSource` 构造代码。

### 5. `CommandRegistry` — 命令注册
```java
public class CommandRegistry {
    public LiteralArgumentBuilder<ServerCommandSource> createAICommand()
    public LiteralArgumentBuilder<ServerCommandSource> createWikiCommand()
    public LiteralArgumentBuilder<ServerCommandSource> createQueryCommand()
    public LiteralArgumentBuilder<ServerCommandSource> createAcceptCommand()
    public LiteralArgumentBuilder<ServerCommandSource> createRejectCommand()
    public LiteralArgumentBuilder<ServerCommandSource> createClearCommand()
    public LiteralArgumentBuilder<ServerCommandSource> createReloadCommand()
}
```
MCP: 7 个方法，每个都是 `CommandManager.literal()` → `.executes()`，内部委托给 `ChatHandler.handleAIQuery()` / `CommandExecutionService.approveCommand()` 等。

### 6. `ToolDispatcher` — 工具分发
```java
public class ToolDispatcher {
    public List<String> dispatch(List<OpenAIClient.ToolCall> toolCalls, ServerPlayerEntity player)
    // 路由：search_knowledge_base → KnowledgeBase
    //       read_knowledge_base → KnowledgeBase
    //       execute_minecraft_command → CommandExecutionService.executeCommand()
    //       get_server_status / get_game_rules / get_debug_info → 内联实现
}
```
消除 `handleAIQuery`(L386-408) 和 `handleConsoleAIQuery`(L707-724) 中完全重复的 if-else 链。

### 改造后调用链

```
玩家 !ai xxx
  → CommandRegistry.createAICommand()
  → ChatHandler.handleAIQuery(player, msg)
     ├─ ThinkingAnimation.start(player)
     ├─ history (保留在 ChatHandler)
     ├─ ChatLog.peek()                         // 聊天上下文
     ├─ PlayerContextBuilder.build(player)      // 玩家状态
     ├─ ToolDispatcher.dispatch(toolCalls)      // 工具路由
     │   ├─→ CommandExecutionService.executeCommand()
     │   │    ├─ needsApproval → 阻塞等审批
     │   │    └─ 直接执行 → executeAsOp()
     │   └─→ KnowledgeBase
     ├─ OpenAIClient.chat() → 响应
     └─ handleResponse() → handleResponse()

管理员 /aiaccept 1
  → CommandRegistry.createAcceptCommand()
  → CommandExecutionService.approveCommand()
     ├─ executeAsOp() ← 统一方法
     └─ pendingFutures.complete()
```

### 修改涉及的现有文件

#### `MCAIMod.java`
- `onInitialize()`: 创建所有新服务实例并注入
- 示例：
```java
ChatLog chatLog = new ChatLog();
ThinkingAnimation anim = new ThinkingAnimation();
PlayerContextBuilder ctxBuilder = new PlayerContextBuilder();
CommandExecutionService cmdExec = new CommandExecutionService();
ToolDispatcher toolDispatcher = new ToolDispatcher(knowledgeBase, cmdExec, ctxBuilder);
this.chatHandler = new ChatHandler(this, chatLog, anim, ctxBuilder, cmdExec, toolDispatcher);
CommandRegistry cmdReg = new CommandRegistry(chatHandler, cmdExec, knowledgeBase);

// 命令注册
dispatcher.register(cmdReg.createAICommand());
dispatcher.register(cmdReg.createWikiCommand());
// ... 每个命令
```
- `onPlayerDisconnect`: `chatHandler.onPlayerDisconnect()` 内部委派给 cmdExec

#### `ChatReviewSystem.java`
- `mod.getChatHandler().peekChatLog()` → `mod.getChatLog().peek()` 或在 ChatHandler 上保留转发方法
- `mod.getChatHandler().clearChatLog()` → 同上
